# Ability

基于多 Agent 协作的桌面 AI 助手，集成 11 个专业 Agent，支持智能表单填写、文件夹分析、代码审查、架构设计、深度研究、文档与演示生成、跨会话记忆、定时任务、多模型切换及网页自动化等能力。

> 📦 如果想要从零开始在本机部署，请阅读详细的 **部署说明**：[DEPLOYMENT.md](./DEPLOYMENT.md)

> **当前版本：v3.0.5-Beta**

## 版本历史

### 3.0.5-Beta（2026-09-03）

#### 办公抽屉文档排版：完完全全还原 WPS / Word

- **run 级样式完整解析与还原**：斜体、下划线、删除线、文字颜色、文字底纹、上标/下标、字号、字体逐一解析并映射为 HTML 内联样式渲染

- **段落级版式还原**：行距（多倍 / 固定 / 最小值）、段前/段后距、左/右缩进、首行缩进（字符与 twip）、对齐、段落底纹、分页控制（段前分页 / 段中保持）

- **分节级还原**：页面尺寸、四向页边距、页眉 / 页脚逐页铺页码、多栏分栏版式

- **顺位字体回退**：本机缺少宋体 / 仿宋 / 楷体等字体时，优先原字体名、再回退到最接近的系统相似字体，尽量贴近发送方机器上的排版

- **显式分页符、空心字、字符间距** 等 Word 特性一并还原

#### 办公抽屉文档交互增强

- **触控板捏合缩放**：文档滚动区支持捏合手势（Ctrl / Meta + 滚轮），连续平滑缩放，不打断普通两指滚动

- **「适应宽度」改进**：改为可开关（再次点击退出），页面在各缩放比例下均居中（不再右偏）

- **分页 / 连续按钮** 标签修正为「点击后的目标动作」，与提示一致

#### 填空字段下划线保真

- **修复 Ethan 填写后下划线消失**：填入字段时继承被替换文字的完整样式（含下划线），不再丢失原填空下划线

#### 导出：除改动处外全部保持一致

- **未编辑导出 = 原始文件原样直出**：导入后未做任何改动时，导出直接回传导入的原始 docx 字节，与 WPS / Word 打开完全一致

- **编辑后格式保留式导出**：无论是用 Ethan 填写、手动编辑还是两者混合，导出都只在原始文档的**被改动段落**上做局部替换，其余内容（表格、页眉页脚、竖排、排版）逐字节不变

- **无法唯一定位改动处时自动回退**整体重建，保证结果不更坏

#### 问题修复

- **修复导出后表格错乱**：修正单元格宽度单位换算错误（此前把 `tcW` 误除以 20，导致表格列被压成细条）

### 3.0.4（2026-08-31）

#### Ethan × 办公抽屉联动：边问边填、所见即所得

- **答案实时同步**：逐题问答时（Ethan 问答卡片或主聊天框两条通道均可），每个答案实时写入抽屉——表格按字段定位精准写入单元格（无定位信息时写入「填写记录」区），文档按锚点/占位符就地替换（无法定位时文末追加问答行）；抽屉标题栏显示「● Ethan 同步中」徽标，答题中途关闭抽屉不影响后台同步

- **导出收尾**：全部填完后直接从抽屉导出成品到原文件同目录（`*_filled` 后缀），所见即所得（含在抽屉中的手动修改）；目标文件已存在时自动加时间戳，绝不覆盖原文件或历史成品；导出失败自动回退原有填写引擎

- **成果卡片**：导出成功后在消息流中展示 OfficeCard 成果卡（文件名 + 「在抽屉中打开」一键跳转）

- **回退保障**：新增「Ethan 抽屉同步」能力开关（插件管理中可随时关闭，关闭后行为与 3.0.3 完全一致）；同步连续失败自动降级为仅对话模式，问答主流程永不受阻；原文件全程只读

#### 办公抽屉文档排版稳定性与表格保留

- **排版不再随抽屉宽度变化**：移除 3.0.3 的「动态重排」行为——页面宽度在文档创建时确定，此后拖宽/缩窄抽屉只调整显示缩放（fit width），分页与折行保持恒定不变

- **docx 表格结构化解析**：导入解析改用 DOMParser 按 XML 结构处理，表格按行保留（每行渲染为「单元格 ｜ 单元格」格式），不再把表格打散成碎片段落；单元格内竖排文字（单字成行）自动合并为正常词语；段落与表格按文档原始顺序提取

- **导出功能修复**：修复自 3.0.2 起导入/导出按钮静默失效的问题（当前 Univer 版本不存在 `exportFile` API）——导出改用 SheetJS（工作簿，实时读取含手动修改的内容）与 `docx`（文档，从快照段落生成）自建实现

#### 问题修复

- **修复锚点占位字段无法作答**：带占位文字的字段在确认处理方式后会再次弹出确认框、陷入死循环（3.0.3 既有问题）；现以字段上的处理决策为准，确认一次后即可正常输入

- **修复表格写入丢失数据**：修正 Univer `getRange` 参数语义误解导致的导入丢列、单格写入零宽度等问题

- **修复编辑页切换冲突**：办公抽屉「工作表/文档」页签改为以 store 单一数据源驱动，程序化导入（Ethan 同步）指定页面后不再被面板本地状态回写覆盖

- **修复抽屉反馈文案被覆盖**：答案同步的反馈提示（如「✓ 已填入：姓名」）不再被容器重建的通用导入文案覆盖

#### 其他

- 新增真实单例的开发调试句柄（仅 DEV 构建）：`window.__debug` 补充 formFillStore / officeDrawerStore / chatStore / formDrawerSyncService，便于控制台联调

#### Ethan Agent 技术路线重构

**防错位机制全面升级：**

- **段落 Run 合并替换法**：解决 Word 文档中占位符被拆成多个 Run 导致的下划线错位问题。遍历段落所有 Run 拼接完整文本，定位占位符后合并替换，全程继承原有格式

- **原生锚点定位法（书签/窗体控件）**：作为优先策略自动执行，100% 继承周边字体、下划线、对齐格式，完全杜绝错位

- **表格关键词锚定法**：不按行列号硬编码定位，通过关键词匹配目标单元格，免疫合并单元格、嵌套表格导致的索引错位

- **合并单元格兼容处理**：写入前判断单元格是否为合并单元格，仅向首单元格写入，避免内容不可见

- **固定列宽保护**：防止长文本撑宽单元格导致整表列宽错位

- **文档结构校验**：填写前后对比段落数、表格数、单元格数，结构异常时自动告警

**填写流程优化：**

- 新增书签/窗体控件优先策略，自动检测并优先使用原生锚点填写

- 智能填写引擎（原"正则匹配"）集成全部防错位机制，作为兜底全能方案

- 多方案降级流程增加可视化动态进度指示器

#### 已知问题

> 实话实说，Ethan Agent 目前仍存在不少 Bug，部分问题受限于技术架构短期内无法彻底修复。我们正在持续努力改进，感谢大家的耐心与期待。

- **下划线错位**：部分文档中占位符的 Run 碎片化程度超出预期，Run 合并替换法可能无法覆盖所有场景

- **填写内容未写入**：某些特殊格式的文档（如复杂嵌套表格、受保护文档）仍可能出现填写失败

- **表格填写错位**：合并单元格 + 嵌套表格的极端场景下，关键词锚定可能定位到错误单元格

- **LLM 字段提取不稳定**：面对复杂文档，LLM 可能遗漏字段或提取到错误的位置信息

- **书签/控件兼容性**：仅支持标准 Word 书签和窗体控件，部分第三方工具生成的文档可能不兼容

### 2.0.0（2026-07-10）

#### 核心新功能：Ethan 表单填写 Agent

**Ethan** 是 2.0.0 的核心功能，一个专门用于信息采集与文档填写的智能 Agent。

**工作流程：**

1. 用户发送文档填写请求（如"帮我填写附件一"）
2. Leader Agent 自动识别并路由给 Ethan
3. Ethan 解析文档，提取所有待填字段
4. 用户在对话中逐字段填写（支持手动输入或 AI 自动生成）
5. 填写完成后自动生成新文档并保存

**支持的文档格式：**

- Word 文档：`.docx`

- Excel 表格：`.xlsx`、`.xls`

- PDF 文档：`.pdf`

- 文本文件：`.txt`、`.md`、`.rtf`、`.csv`

- 标记语言：`.html`、`.htm`、`.json`、`.yaml`、`.yml`、`.xml`

**特色功能：**

- **字段选择界面**：用户可勾选需要填写的字段，跳过不需要的

- **文件选择界面**：文件夹中有多个文档时，让用户选择目标文档

- **AI 自动生成**：对每个字段，用户可选择让 AI 根据上下文自动生成内容

- **自然语言理解**：用户可以用自然语言交互（"下一个"、"跳过"、"帮我写"、"完成"等）

- **会话锁定**：填写过程中所有消息直接路由给 Ethan，不会被其他 Agent 干扰

## 定时任务

在「定时任务」页面可以创建周期性自动执行的任务，基于 cron 表达式调度，支持 5 字段语法：

```
分钟 小时 日 月 星期几
```

常用示例：

| 表达式           | 含义            |
| ------------- | ------------- |
| `0 9 * * 1-5` | 工作日每天早上 9 点   |
| `0 8 * * 1`   | 每周一早上 8 点     |
| `0 10 1 * *`  | 每月 1 号上午 10 点 |

创建任务时需指定一个 Agent 模式和一个任务描述，到达调度时间后对应 Agent 会自动执行。
